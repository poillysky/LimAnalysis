# 车间异常与不良分析平台（含 FACA）完整设计报告

- 版本：V1.0
- 日期：2026年10月
- 状态：初步设计（基于当前仅能通过网页导出 CSV 的约束）
- 入库说明：正文按你提供的报告整理；与「两套 Postgres」的对齐见 [04-two-database.md](./04-two-database.md)。

---

## 1. 项目概述

### 1.1 背景

车间已有自动外观测量设备与注塑机实时数据。公司 SFC 可导出相关数据，但暂无正式 API。需要本地化的异常 / 不良 / 准实时分析 / FACA 平台，做到数据自主掌控、异常快发现、不良根因分析与纠正措施闭环。

### 1.2 目标

- 稳定从 SFC 网页同步多项目数据到本地。
- 低耦合、可扩展的分析平台。
- 准实时异常监控、多维不良分析、工艺参数关联。
- FACA（失效分析与纠正措施）标准化流程（先做基础版）。
- 将来若有正式 API，只替换采集层。

### 1.3 建设范围（当前阶段）

- 数据采集（网页 CSV）
- 本地数据仓库
- 核心分析（不良分布、异常监控、基础关联）
- 基础可视化与查询
- FACA 流程基础支持

后续可扩展：高级 SPC、智能根因推荐、自动预警规则引擎、完整 8D/FACA、移动端。

## 2. 需求分析

### 2.1 功能需求（初步）

| 模块 | 核心功能 |
| --- | --- |
| 数据采集 | 多项目定时拉取 SFC CSV，校验、入库、失败告警 |
| 数据管理 | 原始存储、清洗、多项目隔离、历史追溯 |
| 异常监控 | 准实时异常列表、阈值/趋势预警、异常统计 |
| 不良分析 | 柏拉图、多维交叉、趋势对比 |
| 关联分析 | 外观不良与注塑工艺参数关联 |
| FACA | 问题记录、原因分析、措施制定与跟踪（基础版） |
| 可视化 | 车间大屏 + 分析查询页 |
| 系统管理 | 多项目配置、同步日志、用户权限（基础） |

### 2.2 非功能需求

- 扩展性：新功能以新增模块 / 表 / 任务为主。
- 可靠性：失败重试 + 告警；数据可重跑。
- 性能：多项目并发同步；查询秒级。
- 可维护性：低耦合、配置驱动、日志完善。
- 安全：本地部署，敏感配置加密。

### 2.3 约束

- 数据源仅能通过 SFC 网页导出 CSV。
- 多项目并行。
- 准实时（分钟级），非毫秒级。

## 3. 总体架构

### 3.1 风格

模块化单体 + 数据分层 + 配置驱动。不拆微服务。

### 3.2 逻辑架构

```
展示层：大屏 / 分析页 / FACA / 管理后台
        HTTP API
应用服务：异常 | 不良分析 | FACA | 配置 | 查询
        │
数据处理：清洗 | Enrichment | 可插拔 Metrics
        │
存储：PostgreSQL（生产库 + Timescale）ODS → DWD → ADS
      PostgreSQL（元数据库）项目/规则/权限/同步配置
        │
采集：多项目导出 CSV | 校验 | 同步日志 | 失败告警
```

### 3.3 原则

1. 采集与计算分离：爬虫只对 ODS 负责。
2. 原始数据只增不改（纠错靠新批次重跑，不 update 业务含义）。
3. 多项目差异全部配置化。
4. 新功能以新增为主。
5. Collector 可替换为正式 API，ODS 以后链路不动。

## 5. 数据架构（报告原文，落库见 `04`）

### 5.1 分层

- **ODS**：原始落地，几乎不加工，保留溯源。
- **DWD**：清洗、去重、类型统一、基础关联。
- **ADS**：给前端/服务查的宽表、结果表。

### 5.2 多项目

业务表强制 `project_id`，索引以 `(project_id, 业务时间)` 为主。

### 5.3 表示例（简化，非正式 DDL）

ODS 外观测量、ADS 不良日汇总等示例见你原稿；正式 DDL 待字段清单确认后另文。

原则：测量明细用 `raw_json` 兜底字段差异；唯一键按真实业务再定（`product_sn + measure_time` 只是示例）。

其他 ADS 按功能新增：异常事件、FACA 主表、工艺关联结果等。

## 6. 模块

### 6.1 Collector

登录 → 选项目 → 导出 CSV → 校验 → 写 ODS → 同步日志。每项目独立配置。失败重试 3 次 + 告警。支持按时间范围补数。

### 6.2 Processor

可单独重跑某项目/某日。清洗、去重、外观与注塑参数关联。指标按插件放 `metrics/`。

### 6.3 Services

`anomaly` / `defect` / `faca`；新功能新包。

### 6.4 API

FastAPI 按业务拆路由；统一响应；权限后期加。

### 6.5 前端

大屏、分析工作台、FACA 工作台。

## 9. 部署

Docker Compose：元数据库、生产库（Timescale）、API、采集+处理任务、Nginx+前端。采集任务后期可与 API 进程拆开。

---

## 10. 分期

**Phase 1**：多项目采集 + ODS + 同步告警；基础清洗与核心 ADS；查询 API + 现有 Vue 骨架验证（不用 Streamlit）。

**Phase 2**：不良多维、异常监控、工艺关联；大屏与分析页；FACA 基础流程。

**Phase 3**：更多指标与规则、权限、移动端、运维与性能。

## 11. 风险

| 风险 | 应对 |

| SFC 页面改版 | 采集独立 + 字段映射配置 + 快速修 |
