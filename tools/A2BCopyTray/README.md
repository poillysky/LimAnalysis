# A2BCopyTray

注塑机 / 外观机站点图片增量复制托盘程序（C# WinForms，自包含单文件 EXE，v1.7.4）。

对齐旧版 `A2BCopyTray` 界面文案与行为，目标路径对齐 LimAnalysis：

| 模式 | 实际写入 |
|------|----------|
| 注塑机 | `{目标共享目录}/{机台号}/{yyyyMMdd}/…` |
| 外观机 | `{目标共享目录}/{项目名}/{外观机号}/GVIMAGES/LIM外观检测/{yyyy.MM.dd}/…` |

## 打包

需要 .NET 8 SDK（仅打包机需要；目标电脑无需安装运行时）：

```powershell
cd tools\A2BCopyTray
.\build.ps1
```

产物：`dist\A2BCopyTray.exe`（self-contained / single-file，约 70MB）。

## 现场使用

1. 把 `A2BCopyTray.exe` 拷到站点目录（建议单独文件夹，放到可写位置）。
2. 双击运行 → 主界面此时是**「已暂停」**，先点托盘图标/主界面的 **「系统配置」**。
3. 选注塑机或外观机，填机台 / 项目、源目录、目标共享目录（可 UNC）。
4. 可配置排除清单、黑白名单、限速、心跳、开机自启、启动后是否暂停。
5. 需要桌面入口就在设置页勾上「桌面快捷方式」，或在部署脚本里跑 `--create-shortcut`。
6. 确认无误后，在主界面点 **「开始监控」** 才开始复制（这是刻意的，见下文「运行状态与暂停」）。

配置写入同目录 `config.json`；日志在 `logs\yyyyMMdd.log`；窗口位置记在 `ui.json`。

## 关键行为

### 运行状态与暂停

界面上的状态只有一个来源（`SyncStatus`），四种取值：

| 状态 | 含义 |
|---|---|
| **已暂停** | 未在监控（**启动后的初始态**，或人工按下暂停） |
| **监控中** | 正在盯着源目录（两次轮询之间的常态） |
| **同步中** | 本轮有文件正在复制（进度条走） |
| **异常** | 配置非法、目标不可达等，见「运行日志」末行 |

**启动后默认停在「已暂停」，必须人工点「开始监控」才动。**
现场要求：程序起来不能自己就开始复制 —— 要先确认设备、源目录、目标共享都就绪，再由人按下开始；
否则源目录里混进的无关文件会被自动搬进分析流水线。

- 这个策略是**持久化**的配置项 `startPaused`（设置页「启动设置」→「启动后暂停」，默认勾选）。
  它与"此刻的运行态"是**两个字段**，别混：
  - `startPaused`（落盘）＝ **启动策略**：起来之后要不要自动开始；
  - `paused`（标 `[JsonIgnore]`，**不落盘**）＝ **当前状态**：此刻有没有在监控。
- 「当前状态」刻意不落盘：如果它跟着配置走，「暂停 → 关机 → 开机自启」会让程序按上次的暂停态起来，
  现场几乎不可能发现。老配置里遗留的 `"paused": true` 会被直接忽略，下次保存自动消失。
- 按钮文案随状态切换：已暂停 →「开始监控」（▶）；监控中 →「暂停监控」（⏸）；
  **同步中 →「停止同步」**（中止本轮复制并停止监控）。
- **开始监控**：立刻跑一轮同步（不等扫描间隔），完成后进入「监控中」持续轮询；
  若本轮有「待稳定」文件，下一轮最多 2 秒再扫，保证新图及时跟上。
- **停止/暂停**：会打断正在进行的本轮同步（含限速等待、重试等待），状态回到「已暂停」。
- 暂停期间托盘图标变橙色（暂停条），主界面徽标同步变橙。
- ⚠️「开机自启」+「启动后暂停」同时勾选时，开机后同样停在暂停态、仍需人工点开始。
  这是合法组合（值班机人工确认后开始），但很容易忘，所以：
  启动日志会打印一条提醒，设置页的提示行也会变成橙色警示。
  想让开机后自动开跑，就把「启动后暂停」取消勾选。

### 性能

- **主循环零阻塞**：判断"文件写完没有"用「连续两轮观察到的大小/时间戳一致 + 文件修改时间已过 `文件释放等待` 秒」
  推算，不再对每个文件做 `Sleep`。已同步的目录扫描成本≈纯枚举。
- 已同步的文件在**任何**耗时判断之前就被跳过。
- UI 进度最多 5 次/秒刷新，大目录不会刷爆消息队列。
- 稳态（无新增/无变更）下不写"本轮同步完成"日志，避免每天上万行空转记录。

#### 实际资源占用（2026-10-13 实测）

测试机 16 逻辑核，源目录按当天目录铺 600 / 5000 个文件，取采样窗口内 CPU 时间增量换算。

| 阶段 | CPU | 说明 |
|---|---|---|
| 启动 | 60–100 ms | 单文件自解压只释放 5 个原生 dll（约 7.9 MB） |
| 启动后约 4 秒 | ≈1.2 核（一次性） | .NET 首次 JIT + 首轮全量扫描，之后回落 |
| 稳态（600 文件） | ≈1.9% 单核 | 轮询间隙 |
| 稳态（5000 文件） | ≈5% 单核（≈0.3% 整机） | 形态是每 `扫描间隔` 一次 150–360 ms 的尖峰 |

内存工作集约 150 MB（稳定不增长），句柄约 420，线程 15–20（全为后台线程）。

不会拖慢机器的原因：同步跑在独立后台线程，不阻塞界面；默认 `比对方式=快速` 只比"大小 + 修改时间"**不读文件内容**；
已同步的文件在判重第一步就被跳过，不产生额外 I/O；界面进度最多 5 次/秒。

需要留意两点：

- 目标为 UNC 共享时，每一轮都会对每个文件做一次跨网络元数据查询。文件数上千且链路较慢时，
  把「扫描间隔」从 5 秒调到 10–15 秒（设置页可改）。
- 不要开 `比对方式=md5`：那会每轮把所有文件完整读一遍，机械盘上会明显卡。


### 正确性

- **先写同目录 `.a2btmp` 再原子改名**，目标上不会出现半截图；临时文件方式不被目标支持时自动降级为直接覆盖复制。
- 残留 `.a2btmp` 每 30 分钟自动清扫一次（超过 10 分钟未改动即视为残留）。
- 目标不允许改写时间戳时，判重自动退化为「目标不旧于源」，**不会每轮全量重传**（并在日志里告警一次）。
- 文件被相机/下游程序占用（ERROR_SHARING_VIOLATION 32/33）算"等下轮"，不算失败；
  连续 10 轮仍不可读才升级为失败告警。
- 递归枚举逐目录容错：某层无权限 / 路径过长只跳过该层，不影响其余文件；不跟随联接点，避免目录环。
- 目标共享不可达时进入 45 秒冷却，冷却期内快速失败，不会每轮卡在 SMB 超时上（旧实现最坏单轮 ~90 秒）。
- 退出时线程 15 秒内收敛；未收敛则不释放底层同步原语，避免后台线程抛 `ObjectDisposedException` 弹框。
- 崩溃自启动前先释放单实例互斥体，避免新进程误判"已在运行"。

### 设备别名（自动派生）

设备别名**不需要也不会手工填写**，它由运行模式算出来：

| 运行模式 | 设备别名 | 示例 |
|---|---|---|
| 注塑机 | 机台号 | `IM-0312` |
| 外观机 | `项目-机台-工站` | `eagle_rcvr-GV-0701-3` |

三段各自去首尾空白，**空段自动跳过**（外观机没填工站 → `eagle_rcvr-GV-0701`）。
一个标识都没有时退回本机主机名，保证日志与心跳始终有可识别的内容。

它是「这台设备是谁」的**唯一来源** —— 日志启动行、主界面「设备别名」、托盘提示、
心跳报文的 `deviceAlias` 与 `clientId` 全部取同一个值，因此不可能出现
「界面显示 A、上报却是 B」的偏差。

> 旧版 `config.json` 里的 `deviceAlias` 字段会被**忽略**（不再读写），下次保存时自动消失。

### 心跳上报

`心跳地址` 留空则不上报。填写后按 `心跳间隔(秒)` POST JSON，**独立线程，不占用同步线程**。

地址容错（与旧版一致）：只写 `10.18.97.189:5000` 会自动补成 `http://10.18.97.189:5000/api/heartbeat`；
已写协议只补路径；显式路径不覆盖。设置页的「测试」按钮可直接发一次并显示响应。

上报字段：`clientId / deviceAlias / hostName / clientVersion / mode / machine / project / station /
clientStatus / paused / source / target / okCount / failCount / totalRuns / lastSync / timestamp`。
其中 `clientId` 与 `deviceAlias` 同为上面派生的设备别名。

只在**状态翻转**时记日志（首次失败、恢复各一条），不会刷屏。

### 排除清单

设置页里是**两行**：

- **默认排除**（只读、始终生效、不可删除）：`temp` · `cache` · `Thumbs`。
  由代码兜底（`AppConfig.DefaultExcludePaths`），即使配置文件里一个排除项都没写也照样生效。
- **自定义排除**（可编辑、可留空）：你自己额外要排的项，每行一条，与默认项**合并生效**。

即 **实际生效 = 内置默认 + 自定义**（去重、忽略大小写，默认项在前）。设置页「实际排除」一行
实时回显合并后的最终清单。

**相对路径的原点是「源目录下的当天日期目录」**（例如源为 `D:\Capture\IM0312`、当天目录为
`20261013\`，则 `rel` 是相对 `20261013\` 的路径，用 `/` 分隔）。

**① 相对名（推荐，最常用）** —— 命中即排除：

| 写法 | 含义 |
|---|---|
| `cache` | 排除**任意层级**下名为 `cache` 的目录 |
| `Thumbs.db` | 排除**任意层级**下这个文件名的文件 |
| `20260101/temp` | 用 `/` 连写多段：只排除这一条相对路径 |
| `*.log`、`IMG_*_raw.*` | 通配：`*` 任意串、`?` 单字符 |
| `*cache*` | 任意层级中名称含 `cache` 的段 |

匹配规则：与**每一个路径段**逐一比对（**整段相等**才算，`temp` 不会命中 `temp2`），
以及**文件名**；若写法里含 `/`，再额外拿**整条相对路径**比一次。不区分大小写，整串锚定。

> 不要写 `.\temp` 或开头带 `\` —— 那会被当成另一个名字，匹配不上。

**② 绝对 / UNC 路径** —— 以 `\\`、`//` 或盘符（`D:`）开头，按**前缀排除整棵子树**：
`\\NAS\Share\tmp`、`D:\A2B\Cache`。

**③ 与黑白名单的区别（容易踩）**：黑名单 / 白名单只比对**完整相对路径**或**文件名**，
**不做路径段匹配** —— 所以 `temp` 写进黑名单是无效的。要按目录名排除，请写进**排除清单**。

旧版的 `excludeDirs`（相对名列表）与 `excludePath`（单值）会在首次启动时**自动迁移**进
`excludePaths`，不再静默丢弃。把鼠标悬停在「默认排除」/「自定义排除」/「白名单」/「黑名单」
输入框上可见完整写法说明。

### 桌面快捷方式

两种方式创建（快捷方式指向 EXE 自身，图标取自 EXE）：

- 设置页「快捷方式」区勾选「在桌面创建快捷方式」→ 保存。
- 命令行（部署脚本用；**程序正在运行时也能执行**，不占单实例锁）：

  ```powershell
  A2BCopyTray.exe --create-shortcut
  A2BCopyTray.exe --remove-shortcut
  ```

  退出码 0 成功 / 1 失败，结果同时写进 `logs\`（程序无控制台）。

> 用 COM 的 `IShellLink` 直接写 `.lnk`，**不走 `WScript.Shell`** —— 后者可能被组策略禁用。

### 窗口与退出行为

- **关窗口 = 收起回托盘，不退出**：点标题栏 X、Alt+F4、外部发来的 `WM_CLOSE` 一律只收起。
  只有托盘菜单的「退出程序」才真正退出。
- 收起之后**再运行一次 EXE（或双击桌面快捷方式）会把隐藏的主界面唤到前台**，
  不会弹一句「已在运行」就完事。
- 系统关机 / 注销时正常退出，不会拦着不让关机。

> 实现要点：`FormClosing` 只对 `WindowsShutDown` / `ApplicationExitCall` 放行；
> 实测外部 `WM_CLOSE` 与任务管理器「结束任务」都会被 .NET 标成 `TaskManagerClosing`
> （两者无法区分），所以**不能**把它当"真退出"，否则任何一个外部关闭请求都会静默杀掉托盘程序。

### 配置校验

保存前会拦下：源=目标、目标位于源目录内部（会造成无限复制）、机台/项目为空、模式非法。

## 说明

- 仅同步「当天」子目录；当天目录不存在时静默等待。
- 源目录日期子目录兼容 `yyyyMMdd` / `yyyy.MM.dd` / `yyyy-MM-dd` 三种命名。
- 只做单向增量，不删除目标上的多余文件（目标清理由 LimAnalysis 侧负责）。
- 单实例：`Global\A2BCopyTray.SingleInstance`。
